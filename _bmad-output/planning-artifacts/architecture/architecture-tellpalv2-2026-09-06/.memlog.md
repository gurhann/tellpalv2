- (decision) AD-1 [ADOPTED]: The content module remains the owner of Story audio experience and LULLABY playback data; asset owns media registration and processing, and category only curates canonical types.
- (decision) AD-2 [ADOPTED]: A narration of the same story has no independent Content identity or CategoryType. Canonical type is STORY; reading versus AUDIO_STORY is a public discovery projection selected per localization.
- (decision) AD-3: Shared LULLABY playback is a single aggregate child of Content, holding cover asset ID, audio asset ID, duration, processing state, and ordered instrument links; its ContentLocalizations carry only title and publication state.
- (decision) AD-4: InstrumentCatalog is content-module reference data with stable code and localized labels; a LULLABY stores instrument IDs plus unique display order, never free text or contributor identities.
- (decision) AD-5: Asset processing is scoped explicitly as LOCALIZATION or CONTENT. STORY narration processing remains localization scoped; LULLABY shared playback processing is content scoped and has no language key.
- (decision) AD-6: Public reads compose localized editorial fields with shared playback fields. New responses expose canonicalType and experienceType separately for stories; lullaby responses expose shared cover/audio/instruments plus the selected locale title.
- (decision) AD-7: CMS writes shared LULLABY playback only in a content-level editor and writes LULLABY localization title/status only in locale editors; CMS cannot create canonical AUDIO_STORY.
- (constraint) Existing Spring Modulith boundaries apply: content depends only on asset.api, category only on content.api and asset.api, and no module imports another module domain or infrastructure.
- (constraint) The migration that removes canonical AUDIO_STORY must fail before schema contraction if such content or category rows exist; importing legacy independent audio stories is a later scoped work item.
- (assumption) Instrument labels are localized in the backend catalog so mobile clients do not embed a divergent instrument-label dictionary.
- (decision) AD-2 refined: StoryNarration is a full-story audio child of ContentLocalization; page audio is retained for reading but does not control AUDIO_STORY eligibility.
- (decision) AD-5 refined: asset processing has target-typed localization and content identities with separate partial unique keys and content-level lookup; asset remains sole processing-state owner.
- (decision) AD-7 added: reading, story audio, and lullaby visibility predicates are independent and composed by content query services through asset.api.
- (decision) AD-4 refined: common lullaby cover reuses existing Content.textlessCoverMediaId; catalog instruments require at least one ordered selection and support retirement without deletion.
- (assumption) AD-5 [ASSUMPTION]: Instrument catalog labels are backend-localized by request locale; the user should validate this display ownership before implementation.
