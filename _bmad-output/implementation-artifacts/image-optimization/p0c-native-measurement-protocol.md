# P0c Native Measurement Protocol Proposal

Status: **DRAFT — preparation complete for protocol definition only**. Proposal revision: `p0c-native-protocol-proposal-v1`, 2026-10-11. Scope: `image-optimization-p0c-1`, Story 1.5.

This artifact makes the [canonical protocol contract](../../specs/spec-image-optimization-1-5-native-measurement-admission/native-measurement-protocol.md) concrete. It proposes observable boundaries and bounded defaults; it is not an executed or accepted native batch. No native build, installation, authenticated request, workload, resource measurement or physical-device qualification was performed to author it. The [device/tool matrix](p0c-device-matrix.json), [entry proposal](p0c-native-entry-proposal.md) and [readiness handoff](p0c-native-readiness.md) supply the remaining preparation evidence. A matrix tool being installed does not make its proposed counter available on a target process.

Read with the [Story 1.5 SPEC](../../specs/spec-image-optimization-1-5-native-measurement-admission/SPEC.md), [client identity/geometry contract](../../specs/spec-publish-time-image-optimization/client-image-contract.md), [parent rendition evaluation](../../specs/spec-publish-time-image-optimization/rendition-evaluation.md) and [approved source-resolution purpose](p0a-reader-geometry-decision.md). Changes to this proposal require a new revision. The later execution freeze must independently bind its exact bytes and all selected records; this draft issues no execution freeze.

## 2. Admission, execution freeze and bounded proposed defaults

Before a batch starts, retain independent receipts for accepted OQ-6 scope, implemented entry and verified entry. Close the affected NATIVE-DEVICE, NATIVE-CANDIDATE, NATIVE-PROTOCOL and NATIVE-DECISIONS gates. Source/output/reference hashes copied from predecessor documents are identity leads, not current file re-verification. The two source-resolution reader reference streams and prior offline codec outputs are not reader-demand or native admissions.

The execution scope must freeze the protocol/corpus/reference/candidate/build/lock/tool hashes; device aliases and observed OS/engine/renderer; admitted delivery and account/access aliases; role/viewport/slot/DPR/fit/alignment; cache preparations; identical journeys; per-cell schedules; counters/units/clocks; quality/resource criteria; and all limits. Changed geometry, bytes, tool, process, clock mapping or cache state creates a new scope/version for affected comparisons. Keep preceding failed/not-run rows intact.

| Setting | Concrete proposal default | Meaning and remaining freeze requirement |
| --- | --- | --- |
| Process counters | Target 1 sample/second, without overlapping collector invocations | Retain actual start/end/return times, samples/gaps and achieved cadence. Slow collectors may make 1 Hz infeasible; a separately frozen changed cadence cannot be silently called 1 Hz. |
| Event traces | Request/cache/decode/ownership/frame events plus allocation traces only where qualified | The selected tool, capture categories and attachment/CPU effects belong in the freeze. Missing allocation/graphics support stays null. |
| Repeats | Five preregistered primary observations for each selected device/role/source/control-or-candidate/journey/cache-mode cell | Apply separately to all three selected cache modes. Schedule failures remain observations. A replacement/retry never removes a primary observation; retry summaries remain separate. |
| Ordering | Paired blocks with alternating control-first/candidate-first order and a recorded random seed for pair/source order | Freeze and publish the complete permutation before execution. Seed and realized ordering are both required. No favorable reordering after a result. |
| Initial baseline | 30 uninterrupted seconds at the declared idle surface, using the last valid counter sample within one planned sampling interval of dispatch as the baseline | Retain the complete baseline series and min/max. Missing boundary sample means unavailable baseline delta; do not borrow another run. |
| Settlement | 30 uninterrupted seconds without declared active work after journey completion and intended owner releases | Collect until the boundary. If active work restarts, reset the idle timer and preserve the interruption. An intended retained onstage decoded image is recorded as a retained owner, not hidden. |
| Finite attempt limits | Journey deadline 120 s; settlement may wait at most 60 s after journey completion; total attempt deadline 180 s from dispatch | These are proposed experiment watchdogs only, not accepted app/network/memory/latency budgets. The freeze must reconcile the exact scripted journey with these limits. Existing shorter application transport deadlines remain active. |
| Collector limit | At most one outstanding invocation per collector; proposed 2 s capture timeout | Timeouts/missed slots are recorded. Stop an owned collector before restart; do not claim samples from overlapping stalled requests. Platform/tool feasibility remains unverified. |
| Retry | At most one new attempt for a transient transport/collector failure after full owned teardown; no automatic retries for identity/integrity/quality rejection, actual termination or resource stop | Preserve the primary failure and `retry_of`; include retried/not-run counts. An application-internal retry is a request in the same attempt, not a replacement observation. |
| Evidence caps | Proposed 10,000 app events and 16 MiB sanitized evidence per attempt; 256 MiB external trace per attempt; predeclared finite schedule | Record the cap hit and stop capture without silently evicting old events. Partial evidence invalidates affected metrics. Caps limit observation storage, not image or process resource consumption. |
| Resource stops | Existing application input/cache/attempt bounds remain controls; new OS/process memory or latency stop limits are **unset** | Freeze explicitly accepted per-device experiment resource stop criteria before any claim needing them. No Python worker watchdog or pixel-plane estimate becomes a mobile budget. |

These fixed proposal defaults permit review. None is an accepted production number. Missing devices, transport/counter instrumentation, first-frame proof or agreed criteria may complete Story 1.5 preparation with explicit gaps. They prevent the affected Story 1.6 run or claim. A separately admitted image-ready-only or fixture-only batch may proceed only within its stated narrower scope after its own gates close.

## 3. Cell and journey definition

A cell is the immutable combination of `scope_id`, `device_alias`, `build_id`, `source_binding_id`, `reference_id`, `arm_id`, `role`, `geometry_id`, `journey_id` and `cache_mode`. Every control/candidate pair uses the same source/reference, device, conditions and journey. Encoding profiles may differ only as declared by the arm. Process observations cover the complete journey, not individual images by inferred attribution.

Initially propose only currently implemented Library listing/recommendation and Story Detail hero surfaces, subject to verified role/candidate delivery and applicable measured or accepted geometry. Choose exact category/content/rendition aliases and a viewport-specific route/scroll script at freeze time. No executable cell is selected by this document. The journey record must declare:

- `list-scroll-reversal-v1`: start Library at the same initial offset; identify rows/items by admitted aliases; give each scroll/reversal a frozen offset or item anchor, duration and dwell; end at the declared idle surface. Record actual offsets, dispatches, missed actions and prefetch.
- `detail-back-overlap-v1`: select the same admitted item, open detail through the existing router, declare the overlap trigger relative to a specific event or frozen elapsed offset, return, then open/return the same declared sequence. Retain whether actual pending work existed; an unobserved overlap cannot be reported as overlap evidence.

Both scripts require concrete geometry/action values in the execution freeze. Fixed-duration actions cannot be replaced after a slow candidate result. If an event-triggered action is used, freeze the event and missing-event deadline for both arms. Start list/detail from equivalent compositions and preserve inherited `cover` fit, aspect ratio, alignment, overlays and embedded-text safe region.

Record actual logical viewport/slot, insets, DPR, orientation/window, text scale, source orientation-normalized dimensions, unclamped `Rw/Rh`, selected rendition dimensions and bounded `Dw/Dh` from the parent two-axis geometry. Compute source shortage from the unclamped demand. Record the actual returned decoded dimensions; requested dimensions alone do not prove decode output or quality. A source-resolution reference or device DPR is not an accepted reader slot.

Normal and enlarged text inspections use the same admitted geometry and framing. Freeze legibility/artwork criteria and paired native inspection of titles/diacritics, fine lines, gradients/banding, color/orientation and applicable alpha. Native quality verdicts remain separate from timing/resource results. A prior offline verdict does not fill them.

Rotation/window, URL renewal, corrupt/oversized input, offline miss, turnover and background/resume are optional separate cells only after their actual implementation/delivery is admitted. Record real versus synthetic origin. Reader turns, listening/animation, production account switching, one/two-decode and current-only/current-plus-next arms remain deferred until separately scoped; this draft neither implements nor qualifies them.

## 4. Three independently proven cache states

Every cache preparation produces a before-dispatch proof tied to the exact final provider key, encoded identity and namespace. Store public digests/aliases of private keys; runtime identity/equality checks use the actual objects. The namespace binds batch/account/access/profile/revision and is owned exclusively by the experiment. Existing `hashCode`-named app caches are controls, not a demonstrated collision-free batch namespace.

| Mode | Required preparation and proof | Runtime outcome retained |
| --- | --- | --- |
| `network_cold` | Fresh experiment namespace; encoded lookup/file inventory confirms no matching file; final decoded provider key has `pending=false`, `keepAlive=false`, `live=false`; probe/feature owner registry confirms no matching listener/keepalive/transfer/decode/promotion. Await actual prior teardown. | Actual requests and payload counts, response/cache disposition, verified encoded-ready and decoded-ready. If no request occurred, record mismatch and do not relabel the attempt network-cold. |
| `disk_warm_decoded_cold` | Exact verified encoded file retained with SHA/bytes/MIME/dimensions/immutable access identity; no matching pending/LRU/live decoded key or listener/keepalive/decoder. Release observer and render owners, await transfer/promotion/storage cleanup, then evict only the exact experiment key and recheck. | Actual integrity-verified file hit and absence/presence of requests. A stale renewal request is preserved; the row is not a pure disk-hit observation. |
| `decoded_warm` | Retain the exact final bounded provider/decode key and matching decoded image under current immutable content/access/session generation; record its `ImageCacheStatus`, owner and retain origin. Precache and display use the same final key. | Synchronous/asynchronous decoded hit, any network/disk/decode work, actual dimensions and owner changes. Changed decode geometry or provider/transfer key invalidates this proof. |

`ImageCache.statusForKey` reports pending/keepAlive/live bookkeeping; its flags do not enumerate every application listener. The experiment owner registry supplies the complementary ownership proof. Clearing the LRU is insufficient if live listeners, in-flight decodes or other retained owners remain. Removing a listener/evicting a key alone is also insufficient to prove HTTP cancellation; record actual owned transport cancel/settlement.

The current providers include a transfer-attempt key. A new application artwork attempt can change decoded identity even when immutable disk bytes match. For decoded-warm observations, create a new **observation ID** while retaining the exact still-current provider/session/transfer generation and recording its originating attempt. Do not forge the application attempt or reuse a stale generation. If the future entry cannot redispatch this matching retained provider without changing generation or if route disposal evicts it, mark the cell unsupported until an explicitly accepted experiment-only retention path is implemented. Never mislabel disk-warm as decoded-warm.

Cache priming happens outside the measured journey but its requests/bytes/owners are separately recorded. It cannot secretly count as zero-cost journey work or bypass renewed authorization. Verify state immediately before dispatch and retain actual post-dispatch hit/miss; a precheck races unless composition/observer ownership is controlled. Global cache reset, deleting accepted app files and mutating accepted cache limits are excluded.

Distinguish application encoded cache from HTTP/OS/server/network caches. Record `http_cache_controlled`, proxy/server cache disclosure, connection reuse and network link state as observed or unknown. The stream payload count does not prove origin fetch or wire bytes. An uncontrolled layer stays disclosed under a network-cold **application** cache label.

## 5. Timing and actual target-frame association

Each current-image dispatch creates `image_observation_id` with run/cell/attempt/session generation, content/revision/rendition and final bounded provider/decode identity. Observer callbacks reject mismatched identities, cancelled/obsolete attempts and closed compositions. Retain rejected callback counts/reasons without promoting them to the current image.

| Milestone | Proposed exact observation seam and interpretation |
| --- | --- |
| `dispatch` | Explicit current-image demand accepted by the experiment driver, immediately before the matching metadata/image request invocation. A list initial load may create several child image observations, all bound to its journey. |
| `metadata_start` / `metadata_complete` | Feature repository request start/response acceptance; separate from image bytes and queue wait. If metadata is already retained, record that disposition instead of fabricating a network metadata duration. |
| `request_start` / `headers_received` / `body_complete` | Owned FileService producer and its actual response stream. Include retry/request/producer identities and partial payload on failure. Content-Length is declared length, not actual delivered bytes. |
| `encoded_ready` | Complete admitted file is available after integrity/MIME/dimensions and required source/revision checks. Body completion or package `FileInfo` alone is insufficient. |
| `decoded_ready` | Matching final bounded provider's `ImageStreamListener.onImage` supplies actual `ImageInfo.image` dimensions and decode sequence; explicit error path retained. Listener receipt proves availability, not onstage painting. |
| `target_draw` | Proposed experiment render probe marks the exact matching decoded image's onstage draw during a real paint in a declared engine frame. A build callback, `imageBuilder`, Future, post-frame callback or offstage precache is insufficient. |
| `first_rasterized_target_frame` | The matching engine `FrameTiming` for the validated first target draw, using its `rasterFinish` timestamp and the identity association below. Record callback receipt time separately because reports are batched. |
| `physical_presentation` | Null unless a separately qualified platform tool observes and associates actual display presentation. Raster finish is never renamed physical presentation. |

**Concrete association proposal, not existing capability:** replace only the experiment rendering leaf with `NativeProbeImage`, resolving the same final bounded CachedNetworkImage provider/key that the current leaf uses. It owns/releases its ImageStream listener and renders the admitted `ui.Image` through an experiment `RenderImage` subclass with unchanged fit/alignment/crop. In its `paint`, capture `PlatformDispatcher.instance.frameData.frameNumber`; after the actual `super.paint` image draw, record image/provider/attempt/decode sequence, current route visibility, viewport intersection and frame number. This avoids attaching the marker to a parent that can paint a placeholder or simply reuse a retained child layer. Do not decode a second unbounded source or change package transport. Listener/renderer ownership and perturbation require explicit verification.

Use `SchedulerBinding.addTimingsCallback` and join this marker to `FrameTiming.frameNumber` in the **same process/engine run**, not by nearest callback receipt. The frame number may be `-1`; that is unavailable, not a valid join. Reports may batch or be dropped. Keep a bounded pending association ledger and preserve gaps/duplicate/ambiguous matches.

The probe requires the exact still-current image, positive visible clipped region, admitted onstage route, no fully covering placeholder/error/opaque overlay and successful paint. During transitions/occlusion or retained-layer reuse where these conditions cannot be proven, reject the marker for this endpoint. A replaced or stale image before frame submission cannot qualify. For decoded-warm with layer reuse, require a separately verified real matching image draw in the recorded frame; do not force an extra repaint merely to create a favorable endpoint without disclosing and freezing that instrumentation effect.

Before accepting this association, on the exact compiled SDK/engine/renderer verify frame API availability, monotonic frame identity, draw/frame mapping under async decode, frame batching, route overlap, placeholder/error, offstage/precache, cancellation, stale completion, retained layers and rotation/window changes. Synthetic tests validate rejection logic only; physical profile verification establishes applicable runtime support. Inspect exact engine provenance and validate clock mapping, rather than treating these current API docs as a version certificate.

If any link fails, set `first_rasterized_target_frame.value=null` with `reason` such as `no_target_draw_probe`, `frame_number_unavailable`, `ambiguous_frame_join`, `offstage_or_occluded`, `dropped_timing_report`, `unverified_clock_mapping` or `target_identity_changed`. Keep decoded/image-ready latency under its own name. Where association exists but the duration clock mapping does not, retain the raw frame receipt and mark the dispatch-to-raster duration unavailable. No placeholder latency or nearest unrelated frame substitutes for it.

## 6. Clocks and duration derivation

Application events propose `dart:developer Timeline.now` in integer microseconds on the Dart VM monotonic timeline clock, with a separate ISO-8601 UTC wall timestamp for provenance. Engine FrameTiming raw timestamps have their own declared epoch; DateTime epoch equality is not assumed. Record `clock_id`, `source`, `unit`, `epoch_description`, `process_run_id` and availability for every timeline. Never calculate elapsed performance time from wall time.

Before dispatch, record calibration receipts proving the exact compiled engine's frame/timeline clock relation. A version-pinned source/API verification and matched frame trace must support any claimed shared epoch. `currentSystemFrameTimeStamp` is the raw engine begin-frame timestamp; it is not current wall time or a universal physical-presentation timestamp. Do not subtract it from `Timeline.now` solely because both expose microseconds. If shared epoch is unverified, preserve separate clock domains and null the cross-domain duration.

For native collectors/host clocks, freeze a documented clock synchronization method. Proposed fallback is at least five timestamped request/response brackets before and after the attempt: record host monotonic send/receive and native clock value, producing an offset interval bounded by the round trip rather than an invented exact offset. Retain all brackets, transform, drift and uncertainty; platform clock API, sleep/background behavior and round-trip semantics need exact implementation verification. Unsynchronized counters can retain process-local sample sequence and capture windows, but cannot be precisely joined to image events. Reset calibration after process/device restart or tool reconnect. No averaging erases uncertain ordering.

Durations require valid monotonic endpoints in the same clock or a verified transform, nonnegative order within uncertainty and the same observation identity. A warm hit can make transfer milestones not applicable; it cannot invent `0` for unobserved work. Known zero payload is valid only when the complete transport/cache proof establishes no request payload. Do not impose `encoded_ready <= decoded_ready` for a decoded-warm observation that legitimately refers to a retained image decoded before dispatch; record `retain_origin` and a warm hit after dispatch rather than hiding the earlier event. Counter sample windows keep begin/end/receipt times, not a falsely instantaneous value.

## 7. Transfer, storage and comparisons

Per journey count actual payload delivered by every owned HTTP response stream, including retries, partial failure, prefetch and requests whose consumers later cancel. Deduplicate shared transport by producer/request ID while retaining its consumer links; do not count the shared body once per image listener. Record request count, declared Content-Length, delivered payload, status category and completion/cancel/error separately. A byte cap may reject a chunk after receipt; the received chunk still belongs to observed transfer accounting. Successful cache lookup does not erase another request made earlier in the journey.

Wire/header/TLS/packet totals remain null unless the selected qualified tool actually measures them. The adapter's payload count may be downstream of HTTP content decoding; pin client/tool semantics and state exactly which representation is counted. Metadata traffic, image traffic and priming are separate subtotals, with an explicit whole-journey total only when all included request classes are instrumented.

Comparison rows name positive control denominators and matched pair identities: `saved_bytes = control_payload_bytes - candidate_payload_bytes`, `saved_percent = 100 * saved_bytes / control_payload_bytes`. Zero/missing control payload means percent unavailable with reason. Keep negative deltas/growth. Never multiply one source as repeated baseline downloads, combine phone/tablet variants without declared weighting or infer native journey traffic from encoded output size.

Storage is a separate inventory of retained original/all-variant/all-revision objects with SHA/bytes/role/profile/revision/retention identity and actual retained count. Experiment disk footprint excludes neither stale owned files nor pending writer reservations; distinguish actual file bytes from reserved capacity. Storage growth can coexist with smaller journey payload. Quality-qualified savings remain unavailable until the separate native quality criterion passes.

## 8. Counter selection, overlap and idle interpretation

Select only counters whose tool/version/permissions/output schema are verified on the declared device/build/process. Link each to the matrix capability receipt. Collectors bind private process identity privately and publish `process_run_id`; PID reuse/restart cannot attach values to the previous run.

| Family | Proposed method and fields | Limits/overlap retained |
| --- | --- | --- |
| Dart | Qualified VM-service/DevTools memory export: `dart_heap_used_bytes`, `dart_heap_capacity_bytes`, `dart_external_bytes` by declared isolate/group/process scope | Profile attachment differs from debugger-free lifecycle. External memory, native allocations and process totals overlap. Unavailable release VM service means null, not a debug counter substituted into release. |
| Flutter image ownership | `ImageCache.currentSize/currentSizeBytes`, `liveImageCount`, `pendingImageCount`, per-key status plus experiment listener/keepalive/transfer/decode/promotion registries | LRU bytes exclude some live/pending/transient ownership and are not process memory. Record owner counts, not invented owner bytes. |
| Raster cache | If supported by compiled engine, frame-scoped `FrameTiming.layerCacheBytes/pictureCacheBytes` and counts | Separate counters and frame windows; absent or unverified support stays null. They are not all graphics/process allocations and must not be added to RSS/PSS/footprint. |
| Android process | Qualified `dumpsys meminfo` capture for exact process: total PSS, available total RSS/private-dirty/swap PSS, plus exact Native Heap/Graphics rows and source units | Output varies by OS/tool; retain raw sanitized row labels/schema. Native Heap allocation and its PSS row are different counters. Graphics can be absent. No summing PSS + RSS + private dirty + native + graphics. |
| Android allocations/graphics | Optional qualified native allocation/event trace and available graphics rows | Tool/API/permission/attachment support and sampling loss are explicit. Allocation totals are not automatically resident process usage. |
| iOS/iPadOS | Qualified Xcode/Instruments process footprint with declared current versus lifetime-high-water semantics; Allocations/VM Tracker/available Metal counters as separate tracks | Exact template/Xcode/OS/process/attachment/export units required. Allocation bytes, footprint and graphics tracks overlap and differ in scope; do not substitute simulator observations or sum them. No privileged API entitlement or new native sampler is assumed. |
| Pixel estimate | `decoded_width * decoded_height * 4`, marked `estimate_sdr_rgba8_pixel_plane_bytes` | One assumed 32-bit SDR pixel plane only; no native/process/transient/renderer allocation measured by it. HDR/color/animation can require different representations. |

For each counter report its own baseline, absolute observed peak, signed peak delta, absolute settled value and signed settled delta. Preserve negative drift. `peak_kind` is `sampled_window`, `event_trace` or `lifetime_high_water`; the last cannot be reported as an attempt-local peak without actual window proof. Polling at 1 Hz can miss transient peaks. Do not turn a final snapshot into a peak or report absence of a captured spike as safe memory.

The baseline and settlement surface, lifecycle state, active/pending transfers/decodes/promotions, listener ownership and intended retained image set are explicit. At journey end dispose only declared experiment offstage owners; preserve active admitted images/session-required media. No forced GC is proposed; if later used, it requires a separate arm and disclosure. Settlement requires no outstanding declared active work, then 30 idle seconds. Existing owner retention at the surface is recorded. A late event resets the timer. Failure to reach it within the frozen 60 s wait is `settlement_timeout`; settled values remain null, while available active snapshots remain labeled active.

Keep baseline-to-baseline drift across paired arms with no truncation to zero. Record network, thermal state/tool, background transitions, GC/events and uncontrolled work. Drift/thermal changes may make a pair incomparable under frozen criteria; retain both raw attempts and the exclusion reason. Process changes cannot be causally assigned solely to image bytes.

## 9. Sampling, overhead and lifecycle records

A sample carries planned slot, actual capture start/end/receipt, collector CPU/wall duration where measured, value/unit/scope, tool, process and clock provenance. Include planned/actual cadence, actual sample count, missed slots/gaps, failed captures, attachment state and trace losses. A missed capture creates an explicit sample row with null and reason; it does not create zero memory.

Before a comparative batch, propose matched no-collector versus recorder/counter-enabled control journeys on the same admitted scope to describe observer perturbation. Record the separate overhead schedule/build differences; quantify collector and app recorder CPU/wall/storage costs where feasible. Counter-free runs cannot magically observe their own native memory, and the before/after difference includes noise. No invented overhead subtraction adjusts candidate metrics. If comparison cannot be measured, keep `overhead.availability=unverified` with cause and limit the conclusion. SDK documentation's illustrative overhead is not a device-specific observation.

Profile performance and debugger-free release-equivalent lifecycle are separate build/cell families. Record debugger/VM-service/profiler attachment and exact binaries; do not pool their values. For background/resume retain lifecycle timestamps, whether collection continued, clock behavior and any unavailable interval. Suspended app timers cannot prove 1 Hz sampling.

Synthetic pressure records its hook and tested handler behavior only. Genuine OS pressure/termination needs actual OS/tool provenance: process lifecycle, reason/code, Android exit evidence or iOS jetsam/crash receipt where available, page size/unit where relevant and last observed boundaries. A restart by itself is `termination_reason_unknown`; it does not prove image causation, OOM or successful recovery. A terminated attempt keeps missing endpoints and all subsequent not-run rows.

## 10. Exact future observation schema

Future raw output is a UTF-8 JSON object with `schema_version: 1`, `record_kind: native_batch_observations`, a frozen `scope` object and the following arrays: `schedule`, `attempts`, `image_observations`, `requests`, `cache_proofs`, `owner_events`, `counter_samples`, `counter_summaries`, `clock_calibrations`, `quality_reviews`, `failures`, `artifacts`. This document creates no fake raw observation file.

Every metric is either a non-boolean finite number with units/provenance or a null accompanied by availability/reason. The common nullable value shape is:

```json
{
  "value": null,
  "availability": "unverified",
  "unit": "us",
  "reason": "target_frame_association_not_implemented",
  "evidence_ref": "p0c-native-entry-proposal.md"
}
```

Availability is `observed`, `unverified`, `unavailable`, `not_applicable` or `not_run`; absence is never silently numeric zero. Evidence refs are sanitized local artifact identifiers, not private paths or access URLs. `historical_only` belongs to readiness provenance; a historical sample is not a current batch observation.

| Record | Required named fields and validation |
| --- | --- |
| `scope` | `scope_id`, `scope_revision`, `protocol_sha256`, `corpus_sha256`, `candidate_manifest_sha256`, `admission_ledger_sha256`, `schedule_sha256`, `build_ids`, `device_aliases`, `tool_ids`, `created_at_utc`, `acceptance_refs`, `limits`, `quality_criteria_ref`, `resource_criteria_ref`. ## 11. Failure retention, stop and final reporting

Retain timeout, cancelled work, corrupt/MIME/dimension/checksum mismatch, source/profile/resource shortage, quality rejection, sampling/trace loss, recorder cap, settlement timeout, thermal/background disruption and actual termination. Stop the affected cell/batch at frozen integrity/admission/instrumentation/resource stop conditions; mark all remaining scheduled rows not-run with cause. Do not continue a comparison using another original, profile, account, process or decoder.

On a permitted retry, create a new `attempt_id` with `retry_of`, await actual experiment-owned cancellation/settlement and rebuild its cache proof. Do not delete old partial bytes, failed endpoints or raw records. A failure whose cleanup cannot settle prevents retry; preserve unresolved owner evidence. A tool crash is not an application crash. A resource-invalid observation may still have valid decoded bytes, while a successful decode does not pass resource criteria.

Publish complete schedule/attempt/failure/not-run counts and sanitized raw-derived records. Per exactly matched cell report observed-value count/denominator, median and min/max, with primary attempts and retries separately visible. Nulls/failures remain in the denominator ledger and are not invented numerical latency samples. Include signed transfer/memory regressions, baseline drift, cache mismatches, uncertainty/overhead and unsupported role/floor/counter gaps. Five-observation pilots establish descriptive evidence only; no production P95, rare-crash rate, crash-free claim or safe preload/concurrency budget follows.

Keep actual private media, raw device/account/process identifiers, credentials/session envelopes, URLs, headers, response bodies, tool traces and signing details outside Git; tracked receipts contain aliases, digests, sanitized categories and provenance. An unsalted low-entropy identity hash is not promised anonymous; use opaque aliases and keep mappings private. Sanitize and verify exports before tracking them. Raw trace receipt/hash can be public without committing the trace. Preserve prior freezes/history and do not overwrite live/original objects. Retention/destruction policy remains OQ-5; this proposal invents no production retention period.

## 12. Primary API/tool references and version limits

Official primary documentation checked 2026-10-11 for proposal feasibility. These pages are rolling references. Exact compiled support, permissions, schemas, exports, attachment effects and device capabilities require later verification; this authoring check performed no workload.

- [Flutter FrameData.frameNumber](https://api.flutter.dev/flutter/dart-ui/FrameData/frameNumber.html), [PlatformDispatcher.frameData](https://api.flutter.dev/flutter/dart-ui/PlatformDispatcher/frameData.html) and [FrameTiming.frameNumber](https://api.flutter.dev/flutter/dart-ui/FrameTiming/frameNumber.html) support the proposed identity join; unavailable/default frame numbers must be handled.
- [Flutter addTimingsCallback](https://api.flutter.dev/flutter/scheduler/SchedulerBinding/addTimingsCallback.html) supplies batched engine timings. Receipt time must remain separate from frame phase timestamps.
- [Flutter FrameTiming](https://api.flutter.dev/flutter/dart-ui/FrameTiming-class.html) names frame/raster-cache metrics; [raw timestamp semantics](https://api.flutter.dev/flutter/dart-ui/FrameTiming/timestampInMicroseconds.html) do not establish DateTime epoch equality.
- [Dart Timeline.now](https://api.dart.dev/dart-developer/Timeline/now.html) describes VM monotonic timeline microseconds; [Flutter currentSystemFrameTimeStamp](https://api.flutter.dev/flutter/scheduler/SchedulerBinding/currentSystemFrameTimeStamp.html) describes raw begin-frame time, not a universal presentation endpoint.

- [Android dumpsys memory diagnostics](https://developer.android.com/tools/dumpsys#meminfo) and [memory quick assessment](https://developer.android.com/topic/performance/memory/guide/tools-overview) describe process/category counters whose exact rows vary by platform.
- [Apple memory tools](https://developer.apple.com/documentation/xcode/gathering-information-about-memory-use) and [Metal memory analysis](https://developer.apple.com/documentation/xcode/analyzing-the-memory-usage-of-your-metal-app) distinguish footprint, allocation and graphics observations; tool support/attachment and export must be established on the physical target.
