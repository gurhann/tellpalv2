## Implemented source

The controlled detail endpoint composes public content, asset and category APIs through the existing Library admission facade. It uses exact content language, current published/reading eligibility, category membership independent of preview position, server audience, scalar credits with exact-language/global fallback and ordered eligible recommendations excluding the selection. Invalid scalars return 400 and unavailable content/mapping returns 404. It exposes metadata and actual original-cover descriptors without protected playback content. Existing module edges are preserved.

The hero worker verifies actual stored bytes, MIME, checksum and safe image dimensions. Source bounds are 20 MiB/40 MP, four owned workers and an eight-second foreground wait. Timed-out workers keep ownership until their real work settles. Tests cover corrupt/missing originals, source overflow and cancellation/timeout admission recovery; these tests are not evidence that a remote provider physically stops a blocked read.

Flutter adds the feature's entity/repository/use case, strict DTO conversion, generated JSON/state/DI/routes, exact identity validation and independent detail/artwork states. Requests and images reject obsolete attempts. Recoverable detail errors, unavailable content and separate artwork retry are localized in TR/EN/PT. The adaptive reference-based surface includes deferred disabled reading/premium action, route-owned narration preference, summary/ordered credits and exact-origin recommendations. Back preserves the existing Library owner and source-detail scroll/preference. The loaded locked cover uses blur and an opaque lock; missing artwork leaves the title/retry readable.

The separate detail cache has 20 retained files, 100 MiB disk budget, four owned attempts, 20 MiB encoded transfer limit and account/language/asset/checksum keys. Disk admission serializes asynchronous retained-file checks and reservations. Checksum/file validation is awaited inside the same owned operation, including cancelled work until its real settlement. Decoding preserves aspect ratio within phone 1080/tablet 1600 width, 2048 height and 16 MiB pixels. Hidden/disposed detail releases its provider and invalidates transfer ownership. Tests cover concurrent near-ceiling reservation, file capacity, oversized body/header, decoder bounds and cancelled unsettled metadata/checksum ownership. Native and physical resource measurements remain pending.

Prepared Library/card routing deduplicates repeated actions and carries category ID, content ID, UI language, content language and READING. **`LibraryScreen` still uses the default `LibraryView(detailEnabled: false)`**: six authorized real-fixture cases passed, while the complete prerequisite matrix remains open. A custom test route exercises the prepared actual callback; this does not certify runtime card integration. No new snapshot images were added.
